# AI行为调查局

《AI行为调查局》是一款把 AI Agent 工程知识转译成调查解谜体验的网页游戏。玩家不会先看到概念讲解，而是通过观察现场、询问角色、收集证物和连接因果，亲手查明一套系统为什么失败；只有结案后，游戏才揭示对应的正式工程知识。

在线游玩：[https://hanghang0013.github.io/ai-behavior-investigation/](https://hanghang0013.github.io/ai-behavior-investigation/)

## 故事背景

一座近未来城市将交通、档案、水务、工坊和应急调度接入“回声网络”。暴雨逼近北岸时，城市仪表仍不断报告正常，现实却开始与报告分离。

玩家作为 AI行为调查局的行为勘验员，需要重建命令进入系统后发生的一切，并遵守调查局的第一守则：

> 让现实，而不是口供，决定是否结案。

七起案件属于同一场“回声网络失序事件”，前案留下的实体、编号和记录会成为后案继续追查的线索。

## 核心玩法

观察场景 → 选择调查点 → 与角色交谈 → 收集证物 → 连接因果 → 操作最终机关 → 揭示术语 → 收入回声档案。

- 案件过程只呈现现象、人物立场和客观证据。
- 正式术语集中在结案揭示与知识卡中。
- 结案按“证物回放 → 玩家判断 → 失败因果链 → 修复链 → 术语映射 → 新情境迁移题”展开。
- 每案独立保存调查进度，也可以按编号连续游玩。
- 已结案件会收入“回声档案”，供玩家回顾知识关系。
- 桌面端和移动端均可完成调查，不依赖拖拽操作。

## 当前案件

| 案件 | 谜面 | 知识范围 |
|---|---|---|
| 01《失控信使案》 | 为什么它确信送达，现实却没有？ | 上下文、工具、验证器、纠错循环与 Harness |
| 02《不断重写的大厅》 | 为什么保存了全部消息，却仍不断重来？ | 上下文质量、稳定前缀、KV Cache、状态栏、压缩与隔离 |

第七案采用同页上下卷结构：上卷处理“能力应该住在哪里”，下卷处理“确实需要训练时如何可靠学习、验证、停止与恢复”。

## 存档说明

- 调查进度会自动写入浏览器 `localStorage`，刷新或关闭网页后仍可继续。
- 存档只属于当前域名、浏览器、设备和用户配置，不提供账号云同步。
- GitHub Pages 与本地 `localhost` 使用不同存档，彼此不会自动迁移。
- 清除网站数据、使用无痕模式或在回声档案中重置案件会删除对应进度。
- 第六、七案使用版本化存档迁移；新增必做交互时会尽量保留旧证物和旧推断，只引导玩家补做新增步骤。

## 设计理念

- 先现象，后术语。
- 知识必须成为谜题解法，而不是附加说明。
- 环境证据优于角色自述，现实终态优于系统的成功回执。
- 故障来自模型、上下文、工具、环境和 Harness 的组合关系，而不是简单归因于“AI 失控”。
- 每案只承担一个核心认知冲突，并为下一案留下可追踪证据。

## 技术与素材

项目使用原生 HTML、CSS 和 JavaScript 构建，调查进度保存在浏览器本地。游戏环境与人物图像位于 `image/`，由 OpenAI 内置图像生成工具生成；关键线索文字由网页界面呈现。

项目不依赖构建工具。克隆仓库后，可在项目根目录启动本地预览：

```bash
python3 -m http.server 8000 --bind 127.0.0.1 --directory public
```

随后访问 [http://127.0.0.1:8000/](http://127.0.0.1:8000/)。根目录保存开发源文件，`public/` 保存 GitHub Pages 发布镜像；提交前应保证两者一致。
