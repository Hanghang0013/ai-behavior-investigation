# AI行为调查局

一个把 AI Agent 工程知识转译成调查解谜体验的网页游戏。玩家先通过场景、对话和证物关系理解系统为何失败，结案后才解锁正式工程概念。

当前包含三起可独立存档、连续游玩的完整案件：

- 案件 01《失控信使案》：上下文、工具、验证、纠错循环与 Harness。
- 案件 02《不断重写的大厅》：上下文质量、稳定前缀、状态栏、分层压缩与隔离。
- 案件 03《失踪的第七码卷宗》：持久化记忆、RAG、混合检索、结构化分块、来源与冲突治理。

## 运行

项目没有构建依赖。推荐只从安全发布目录启动静态服务器：

```bash
bash scripts/build-public.sh
python3 -m http.server 8080 --directory public
```

然后访问 `http://localhost:8080`。系列主页负责介绍《AI行为调查局》，点击“进入案件目录”后前往独立的“回声档案”页面选择案件。玩家也可以在案件结案页直接进入下一案，连续游玩。

终端必须保持运行；关闭命令或电脑休眠后，`localhost` 地址就会停止服务。请勿从项目根目录启动服务器，否则根目录中的本地资料也可能被访问。

调查进度保存在浏览器 `localStorage` 中；结案后可在“回声档案”反复回顾知识卡，也可清空进度重新游玩。

## 生成安全发布包

运行：

```bash
bash scripts/build-public.sh
```

脚本会把三案所需的页面、样式、脚本和游戏图片复制到 `public/`。该目录使用严格白名单；原书 PDF、设计文档及其他素材不会进入发布包。修改根目录源码后，需要重新运行脚本同步 `public/`。

## 使用 GitHub Pages 分享

项目已经包含 `.github/workflows/deploy-pages.yml`：

1. 在 GitHub 创建仓库，将本项目推送到 `main` 分支。
2. 打开仓库的 **Settings → Pages**，将发布来源设置为 **GitHub Actions**。
3. 推送代码，或在 **Actions** 页面手动运行 `Deploy game to GitHub Pages`。
4. 工作流成功后，部署页面会显示可公开访问的网址。

如果仓库默认分支不是 `main`，请同步修改工作流中的分支名。自定义域名不是必需项。

根目录的 `.gitignore` 已排除原书 PDF 和人物原图备份。首次推送前仍建议用 `git status` 确认 PDF 没有进入待提交文件；如果它此前已被其他仓库跟踪，单独添加 `.gitignore` 不会自动取消跟踪。

## 首案知识范围

- 决策时可见的信息：上下文 / 观察空间
- 可执行的外部动作：工具 / 动作空间
- 现实终态优于自我声明：验证器
- 约束、验证、纠错和状态维护：Harness
- 可靠循环：观察 → 判断 → 行动 → 验证 → 记录 → 继续 / 停止

## 第三案知识范围

- 跨会话保留可维护事实：持久化记忆 / User as Code
- 先检索证据，再增强上下文并生成：RAG
- 精确匹配与语义召回并用：BM25 + Dense Retrieval
- 合并候选并重新排序：融合 / Rerank
- 保留结构、来源、实体与时间：结构感知分块 / 上下文化分块
- 概览导航、详情回取、冲突留痕：两层记忆与知识治理
